# 简道云工时确认助手

直接读取简道云数据列表，不扫描钉钉消息。把可发布工作流与用户配置分开：本 Skill 只放通用逻辑，姓名、URL、字段和值保存在 `~/.config/jiandaoyun-timesheet-review/profiles/*.json`。

## 选择工作流

1. 列出 profile 目录中的 JSON。
2. 只有一个 profile 时自动使用；用户点名时匹配 `profileName` 或 `personName`；多个候选且无法判断时只问一次。
3. 没有 profile，或用户要求换人、换表、重新配置时，执行“启发式首次配置”。
4. 巡检使用“只读提取”；只有用户在当前结果中明确选择 `A` 编号后，才执行“确认记录”。
5. 定时任务永远只读；空结果可静默，登录失效必须打开可见扫码页并通知用户。

执行前按需读取 [profile-schema.md](references/profile-schema.md)。浏览器操作遵循可用的 `agent-browser` Skill。

## 登录态与接口模式

默认使用 `session_api`：浏览器只负责建立登录态、生成当前 CSRF/会话字段和登录失效时显示扫码页；数据查询与确认优先通过简道云页面实际使用的同源接口完成。

### 凭据

- 优先复用 profile 的 `browserProfilePath`，通过 `agent-browser --profile` 持久化浏览器配置目录。该目录必须在 Skill 目录外、权限为 `0700`，仅允许当前操作系统用户访问；它会保存简道云需要的 Cookie、localStorage、IndexedDB 和会话上下文。
- 单独提供 `auth_token` 不能独立认证；不要要求用户把 token 粘贴到聊天。若用户通过本机受保护文件或标准输入交付认证信息，只把它作为初始化材料，不能替代扫码登录或持久化浏览器 Profile；绝不回显凭据。
- 首次扫码登录后，保持同一个 `browserProfilePath` 运行后续任务。不要每次把 Cookie 拆出、重组到新会话，避免 `Session instance mismatch`。
- `authStatePath` 仅作为一次性迁移/恢复选项；如果使用它，必须保存完整 Playwright 状态且权限为 `0600`，不得把其中的值写入日志或 Skill。长期运行优先使用 `browserProfilePath`。
- 不修改 Cookie 的到期时间，不用空请求刷“保活”。客户端到期时间不代表服务端一定持续有效；每次任务开始做一次只读鉴权探测即可。
- 出现 401、登录页、扫码提示或 `Session instance mismatch` 时，继续使用同一个 Profile 打开可见登录页请用户扫码；成功后不要更换 Profile，也不要复制 Cookie。

### 接口发现与调用

- 接口路径、请求体和请求头以当前简道云页面真实请求为准，不猜测私有接口参数。
- 首次配置或简道云升级后，通过只读页面请求捕获查询模板；确认接口模板只允许在用户已经授权的 A 项确认过程中捕获。
- 将接口模板存入 profile 同目录的私有运行时文件，不写入发布包；不得存入 Cookie、CSRF token、用户 token 或一次性请求 ID。
- 调用接口时在已登录的 `jiandaoyun.com` 页面上下文中执行，由当前浏览器携带 Cookie，并使用本次页面生成的 CSRF/版本头。
- 接口不可用、返回结构变化或模板校验失败时，退回可见浏览器操作，不得试探性提交。

## 启发式首次配置

采用“先观察、后追问、再预览”的渐进式交互，不一次抛出长问卷。

1. 先请用户提供简道云数据列表 URL；若当前浏览器已经打开目标列表，直接复用。
2. 使用可见浏览器打开 URL。若出现登录、扫码或身份验证页，停在可见页面请用户扫码；登录完成前不得把页面无数据解释为空结果。
3. 登录后读取页面标题、表头、当前筛选条件和少量样例行，自动推断：
   - 表单名称；
   - 人员字段候选：`人员`、`员工`、`姓名`、`提交人`；
   - 状态字段候选：`流程状态`、`状态`、`审批状态`；
   - 节点字段候选：`当前节点`、`审批节点`、`节点`；
   - 负责人字段候选：`当前负责人`、`负责人`、`审批人`；
   - 项目经理字段候选；
   - 当前视图中的人员筛选值；
   - “进行中”和“确认”对应的实际值；
   - 从列表 URL 的 app 标识推导待办 URL。
4. 对置信度高且唯一的项直接采用；只询问不能唯一推断的内容。每轮最多问 1–3 个短问题，优先问：
   - 查当前用户还是指定人员；
   - 哪个字段代表该人员；
   - 哪个状态表示尚未完成；
   - 哪个节点表示需要确认。
5. 给出配置预览：profile 名、人员、表单、筛选条件、分类依据、输出列、登录方式。用户确认后再保存。
6. profile 文件名使用稳定的英文或拼音 slug。不要把 profile 写进本 Skill 目录，不要把真实配置放入发布包、示例或日志。
7. 首次只读运行一次，让用户核对分类和输出列。只有用户明确要求时才创建定时任务。

当用户说“换成李四”“改用另一张表”“确认节点改为经理确认”“多显示成本中心”“隐藏提交时间”时，基于当前 profile 修改，先预览差异，再保存。

## 只读提取

### 打开列表和登录

若配置了 `browserProfilePath`，用同一个 `--profile` 打开 profile 的 `listUrl`。只有在没有 Profile、或明确执行一次性迁移时才加载 `authStatePath`。以下任一情况视为未登录：

- URL 进入 `/signin`、`/login` 或租户登录页；
- 页面显示扫码、登录或身份验证提示；
- 提取结果为 `authenticated=false`。

未登录时，使用可见浏览器打开 profile 的 `loginUrl`；未配置时打开 `https://www.jiandaoyun.com/`。停在扫码页通知用户，不尝试绕过登录。用户确认登录后重新打开列表并更新最小认证状态。

### 提取和分页

先校验 profile：

```bash
node scripts/validate_profile.mjs PROFILE.json
```

将 profile 注入浏览器提取脚本，避免读取整页文本：

```bash
node scripts/build_browser_script.mjs PROFILE.json | agent-browser eval --stdin
```

提取器按页面真实表头映射列，只保留同时满足以下条件的记录：

- 人员字段匹配 `personName`；
- 状态字段等于 `values.activeStatus`；
- 当前节点字段等于 `values.confirmNode`。

结果分类：

- `mine`：当前负责人包含 `personName`，编号为 `A1、A2...`，本人可确认；
- `needManagerFollowUp`：当前负责人不包含 `personName`，编号为 `C1、C2...`，仅用于催项目经理或当前负责人。

若 `totalPages > currentPage`，点击 `.x-pagination .page-turn-next:not(.page-btn-disabled)`，等待表格内容变化后继续，直到最后一页；按 `recordId` 去重。项目经理不是本人也必须呈现，不得把 `C` 类记录当作可确认记录。

### 输出

先显示总数及 A/C 数量，再把所有记录放进同一张 Markdown 表。列顺序为：`编号`、`处理类型`，随后是 profile 的 `displayFields`；空值显示 `—`。

常规输出不展示 `recordId`，但当前会话必须保留编号到 `recordId` 的映射。项目经理与当前负责人不一致时，以当前负责人作为实际待处理人并提示差异。

若为空，输出“当前没有处于目标确认节点的进行中工时”。定时任务配置了静默时不发送空结果。

## 确认记录

数据巡检默认只读。只有用户在当前结果中明确选择一个或多个 `A` 编号，或明确说“确认全部 A 项”，才可以处理。不得确认 `C` 编号，不得把“看看、检查、执行一次、列出来”解释为确认授权。

授权必须绑定当前结果中的 `recordId`、业务匹配键和分类。用户授权后不再逐条回到列表重新检查；只有接口返回状态冲突时才重新查询该条记录。

1. 从当前结果映射中取出所有用户选择的 A 项；任何 C 项、未知编号或已过期映射立即拒绝。
2. 只查询一次待办列表，按 `tableName` 和所有非空 `matchFields` 为每个 A 项定位唯一的 `instanceId`、`taskId`；零条或多条都跳过，禁止猜测。
3. 若已有已验证的确认接口模板，在当前浏览器登录态内直接逐条或小批量提交“确认”。不得提交作废、终止、退回或其他动作。
4. 若尚无模板，只对第一条授权记录使用可见页面确认并捕获真实请求模板；模板校验成功后，其余授权记录改走接口。不得为了学习模板操作未授权记录。
5. 单条返回“已处理、任务不存在、负责人变化”时标记为跳过，不自动改用其他动作，也不盲目重试。
6. 全部提交完成后只统一回查一次列表；确认已不再属于 `mine` 才报告成功。部分失败时分别报告成功、跳过和失败编号。

## 定时任务

- 只执行只读提取，不确认、不作废、不催办、不修改数据；
- profile 必须在任务提示中明确指定，避免多 profile 时选错；
- 保留用户指定的时区、频率、通知渠道和空结果策略；
- 登录失效时打开可见扫码页并通知用户；
- 不读取钉钉，不逐条打开已完成记录。
