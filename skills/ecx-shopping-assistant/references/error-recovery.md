# 异常恢复手册

## 总原则

- 区分传输成功、业务成功、写入生效和最终支付成功。
- 每次写操作后用独立只读查询验证。
- 从最近一个可信只读状态恢复，禁止盲目重试写操作。
- 禁止用历史记录、缓存或响应中的局部字段证明本次操作成功。

## 商品搜索

### 搜索返回 0 件

1. 检查是否仍处于匿名或错误 `company_id`。
2. 完成会员授权并识别实际商城。
3. 在会员商城重新搜索。
4. 仍无可靠结果时才报告未找到。

### 返回无关商品

- 核对名称、简介、分类与规格。
- 将过滤疑似失效的结果视为无可靠候选。
- 禁止因接口返回数量大于 0 就继续下单。

## 授权

### 一次性 code 失效

- 重新创建授权流程。
- 使用新 `state` 与新 code。
- 禁止重复兑换旧 code。

### 授权成功但会员工具 401

- 检查授权是否由购物连接器可识别的同一授权服务实例签发。
- 重新授权后从会员状态与 `company_id` 核验继续。
- 禁止在对话中要求用户粘贴 JWT。

## 购物车

### 工具报告成功但勾选未变化

1. 重新读取购物车。
2. 若状态未变，视为失败。
3. 停止结算，报告连接器参数或版本不兼容。
4. 禁止绕过结构化连接器直调内部 API。

### 结算包含旧商品

1. 停止订单流程。
2. 取消其他购物车行，仅勾选目标行。
3. 回读验证。
4. 重新结算预览。

## 优惠券

### 领券报告成功但券未到账

1. 重新查询会员券。
2. 未出现对应券则判定本次领取失败。
3. 禁止用历史券记录冒充本次成功。
4. 继续下单前说明将不依赖该券，必要时请求用户确认新金额。

### 券已到账但结算未抵扣

- 检查门槛、适用店铺、商品范围和有效期。
- 用结算预览验证最终抵扣。
- 禁止承诺券面价值一定全部生效。

## 订单

### HTTP 200 但业务失败

检查：

- 是否返回有效 `order_id`。
- 是否含错误消息或缺失字段提示。
- 金额与预览是否一致。

任何一项不满足都视为失败，不生成支付二维码。

### 缺少接收人或分销字段

- 从稳定地址映射完整 receiver 字段。
- 根据当前工具契约补齐必填字段。
- 重新 dry-run，禁止复用旧确认 token。

## 支付

### 返回 `code_url` 且报告系统繁忙

分别表达：

- 订单：已创建或未创建。
- 二维码内容：是否已返回并可渲染。
- 支付发起：异常或待确认。
- 最终支付：根据交易状态，通常仍为 `NOTPAY`。

禁止仅因二维码可扫描就宣称支付发起或支付成功。

### 二维码过期

1. 查询订单是否仍为可支付状态。
2. 确认未支付、未关闭。
3. 重新 dry-run 并生成新二维码。
4. 禁止复用旧 `code_url`。

### 状态查询命中缓存

- 禁止使用缓存结果宣布支付成功。
- 使用交易详情的实时查询；随后交叉核验订单详情。
- 限制轮询次数，持续不确定时提示稍后主动查询。

## 用户可见错误模板

### 可恢复

「当前已完成：{可信步骤}。在 {失败步骤} 发现 {真实错误}，因此尚未继续 {后续敏感步骤}。完成 {恢复动作} 后可从该步骤继续；继续前将重新核验订单状态，避免重复创建订单。」

### 金额变化

「结算金额已从 ¥{old} 变为 ¥{new}，变化来自 {运费/优惠/价格}。旧确认已失效，需要按新金额重新确认后才能下单。」

### 支付异常

「订单已创建，但支付服务返回 {错误}。二维码内容由商城后端返回并已展示，但当前订单仍为 {status}，不能视为支付成功。建议 {重试/稍后查询}。」
