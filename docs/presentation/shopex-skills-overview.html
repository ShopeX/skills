为什么需要 Skill 主仓？

避免各产品线各自维护、命名混乱、重复建设，让 Agent 能力可发现、可安装、可治理。

🎯

统一入口

一个官方仓库，所有产品 Skill 集中发布。用户通过 Skills CLI 按需安装，无需手工复制散落文件。

📦

按需安装

支持 Cursor、Claude Code、Codex、Gemini CLI、Copilot 等多 Agent；安装单个 Skill 或全量安装均可。

🔒

可治理

PR 评审、CODEOWNERS、CI 校验、SemVer 发布、安全审查——公共 Skill 等同于可执行供应链内容。

🧩

小而专，不造万能 Skill

产品 Skill 承载专业知识；suite-* 做端到端流程；router-* 处理入口歧义。拒绝一个巨型 Skill 包打天下。

仓库结构

一层扁平目录，Skill 名称全局唯一，每个 Skill 必须自包含。

agent-skills/
├── skills/                         # 所有 Skill，一层扁平
│   ├── ecx-shopping-assistant/
│   │   ├── SKILL.md                # 必需
│   │   ├── scripts/                # 可选：确定性脚本
│   │   ├── references/             # 可选：详细资料
│   │   └── assets/                 # 可选：模板与静态资源
│   └── common-jiandaoyun-timesheet-review/
├── docs/                           # 命名、维护、调研文档
├── scripts/validate_skills.py      # 本地 / CI 校验
├── .github/                        # PR 模板、CODEOWNERS、CI
├── CONTRIBUTING.md
└── README.md
三条强制规则
  1. 目录名、SKILL.md 的 name、安装时的 --skill <name> 必须完全一致
  2. 每个 Skill 必须自包含，禁止引用仓库根目录或兄弟 Skill 的文件
  3. 产品归属写入全局唯一名称：ecx-*、oms-*、digios-*；跨产品用 common-*，组合流程用 suite-*，路由用 router-*

命名与分类规范

名称即契约：Agent 靠 description 决定是否加载，团队靠前缀识别归属。

类别 语法 用途 示例
产品 <product>-<capability> 单产品内的专业任务 ecx-order-diagnosis
共享 common-<capability> 至少两个产品共同使用 common-api-contract-review
组合 suite-<workflow> 编排多能力完成完整流程 suite-release-readiness
路由 router-<domain> 请求不明确时选择产品或 Skill router-shopex-product

产品前缀

ecx-oms-digios-

字符约束

小写字母、数字、单连字符；1–64 字符；正则 ^[a-z0-9]+(?:-[a-z0-9]+)*$

禁止

helper、utils、manager、版本号、大写、下划线、多层目录

✅ 推荐

  • ecx-shopping-assistant
  • oms-inventory-reconcile
  • digios-report-analysis

❌ 反例

  • ecshopx — 只有产品名，无能力
  • ECX_Order_Debug — 大写、下划线
  • oms-tool-v2 — 空泛 + 版本号

Step 1 · 提交前检查

  • 阅读 docs/NAMING.md
  • 搜索现有 Skill，避免重复能力
  • 明确产品 scope、触发边界、Owner
  • 新产品前缀须先登记注册表

Step 2 · 创建 Skill

cp -R .github/skill-template \
  skills/ecx-order-diagnosis

python3 scripts/validate_skills.py

SKILL.md 最小格式

---
name: ecx-order-diagnosis
description: Diagnose ECX order lifecycle failures. Use when an ECX order fails during creation, payment callbacks, fulfillment, or status transitions.
---

# ECX Order Diagnosis

写给 Agent 的可执行指令，而不是产品宣传文案。

PR 必备内容与评审规则

Skill 的质量核心在「触发正确」——必须证明该触发时触发、不该触发时不触发。

PR 必须包含

  • 用户问题与实际收益说明
  • 5 个应触发样例
  • 5 个不应触发样例
  • 2 个相邻 Skill 边界样例
  • 测试命令和真实执行结果
  • 所需工具、网络、权限和外部依赖
  • Skill Owner 与备份 Owner

评审分工

ecx-* / oms-*对应产品 Owner + Maintainer
common-*至少 2 个产品 Owner + Maintainer
suite-* / router-*Maintainer + 受影响产品 Owner
含脚本 / 生产写操作额外 Security Reviewer

写作原则

✅ 只写商派特有、易错、必须一致的内容

✅ SKILL.md 推荐 ≤ 500 行，细节放 references/

✅ 确定性操作放 scripts/

❌ 不写营销文案或关键词堆砌

❌ 不提交凭据、客户数据

❌ 不在 Skill 目录内加 README / CHANGELOG

业界一般做法

商派方案对齐开放标准与主流生态，而非绑定单一厂商。

来源 做法 商派对齐点
Agent Skills 开放标准
agentskills.io		 目录 + SKILL.md；name / description 必填；可选 scripts/、references/、assets/ 校验脚本以此标准为下限；description 必须说明「做什么 + 何时用」
Anthropic 官方示例仓
anthropics/skills		 单仓多 Skill；skills/<name>/ 扁平结构；每 Skill 自包含 采用相同扁平目录；Claude Plugin 作为可选包装，非唯一分发方式
Skills CLI / skills.sh
skills.sh		 npx skills add owner/repo --skill name；跨 Agent 安装与更新 README 提供复制即用的安装命令；生产环境锁定 tag 或 commit SHA
OpenAI Codex 旧 openai/skills 已废弃；以开放 SKILL.md + Plugin 包装为主 不以旧仓为长期标准；按需增加 Codex Plugin 层

业界共识

  • 小 Skill、专 Skill，避免万能大包
  • 渐进披露：正文精简，references 按需读取
  • 自包含：安装后独立可用
  • SemVer 仓库 tag 发布，Skill 名不带版本
  • PR + CI + Owner 治理

商派差异化

  • 产品前缀注册表（ecx / oms / digios）
  • common-* / suite-* / router-* 分层
  • 触发正反例作为 PR 硬性要求
  • 季度质量审查 + 安全基线

总结与下一步

本仓库 = 商派 Agent 能力的唯一官方主仓。后续所有 Skill 贡献走同一套流程。

对贡献者

  1. Fork → 分支 → 按命名规范创建 Skill
  2. 运行 python3 scripts/validate_skills.py
  3. PR 附触发样例与测试结果
  4. 等待 Owner Review → 合并
  5. 同步更新 README Skill 清单

对使用者

npx skills add ShopeX/skills --list
npx skills add ShopeX/skills --skill ecx-shopping-assistant
npx skills check
npx skills update

客户端不支持 CLI 时，复制完整 skills/<name>/ 目录到 Agent Skills 目录。
